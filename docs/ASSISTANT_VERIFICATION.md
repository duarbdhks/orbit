## 모델 품질 비교

고정된 합성 사실 다섯 종류를 여섯 모델·effort 조합에 같은 순서로 넣었다. 실제 설정, effort 누락, 요약, 권한 부족, 상충한 일정 사례다. 총 30건을 실제 Codex로 실행했다. 단순 필수 정보 검사에서는 Luna low의 일정 요약 한 건이 이전 제안일을 누락했고 나머지 29건은 통과했다.

이 비교는 도구가 없는 짧은 합성 문항이다. 실제 Slack의 긴 지침·도구 선택까지 품질을 보장하지 않는다. 그래서 실환경에서 실패한 Luna medium을 기본값으로 남기지 않았고, low도 자동 승격하지 않았다. 각 요청의 대기시간은 남겼지만 이 표본으로 일반적인 속도 우위를 주장하지 않는다.

## 한계

- 채널 수집과 DM 조회 모두 오래된 스레드의 새 답글을 놓칠 수 있다. 페이지를 다 읽었다는 사실과 Slack 전체 대화를 확인했다는 주장을 구분한다.
- 대기 GIF를 항상 쓰려면 고정된 QM의 이모지 선택 동작이 개선돼야 한다. 현재는 기본 리액션 대체 경로를 유지한다.
- 기존 Orbit 예약 세 개는 계속 중지 상태다. webhook과 QM 기본 예약 상태는 변경하지 않았다.
- 재부팅과 장기간 인증 갱신은 이번 검증 범위가 아니다.

## 적용 원칙

- `Fix Root Causes`로 하위·후속 턴의 인증 경로를 고쳤다.
- `Model the Domain`으로 Jev 판단을 네 축과 다섯 실행 경로로 나눴다.
- `Laziness Protocol`로 고정된 QM과 기존 MCP·리액션 기능을 재사용했다.
- `Test Behavior, Not Implementation`으로 실제 요청 모델, 최종 Slack 답변과 권한 실패를 검증했다.
